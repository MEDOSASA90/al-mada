# حزمة تسليم مشروع منصة العيادات الطبية إلى وكيل البرمجة

## مهم قبل البدء
المشروع **لم يبدأ تنفيذه بعد**. هذه الحزمة هي مرجع تأسيسي لوكيل البرمجة، وليست دليلًا على أن أي وظيفة تم تنفيذها أو اختبارها.

## ترتيب القراءة الإلزامي
0. `AGENT_INSTRUCTIONS.md` ثم `docs/00_BUILD_DIRECTIVE_AR.md` — توجيه البناء الكامل وترتيب الأولوية وحسم التعارضات. **اقرأهما أولًا.** و`docs/FEATURE_INVENTORY_SEED.md` — بذرة جرد الميزات.
1. `docs/clinic_saas_blueprint_v2.md` — المخطط الأصلي الكامل للمشروع (الأقسام 9–31 والملحق الحاكم تسبق الأقسام 1–8 عند التعارض).
2. `docs/PRODUCT_REQUIREMENTS.md` — نطاق المنتج وما يجب أن يفعله.
3. `docs/AI_ASSISTANTS_REQUIREMENTS.md` — المواصفات التنفيذية للذكاء الاصطناعي؛ الأولوية لمساعد الطبيب ثم المساعد الإداري ثم الاستقبال.
4. `docs/ARCHITECTURE_AND_SECURITY.md` — قرارات التصميم والأمان الأساسية.
5. `docs/IMPLEMENTATION_PLAN.md` — مراحل التنفيذ وبوابات التسليم.
6. `docs/ACCEPTANCE_CHECKLIST.md` — شروط القبول والاختبارات.
7. `docs/OPEN_DECISIONS.md` — أمور لا يجوز للوكيل اختراع إجابات لها.
8. `AGENT_INSTRUCTIONS.md` — التعليمات التي يجب على الوكيل اتباعها.

## قرار الذكاء الاصطناعي المعتمد مبدئيًا
مساعد الطبيب هو الأولوية الأولى، يليه المساعد الإداري، ثم مساعد الاستقبال. البنية هجينة: Backend للصلاحيات والبيانات وقواعد العمل، خدمة AI مستقلة، n8n للأتمتة والتكاملات، وطابور مهام للعمليات الطويلة. التفاصيل واختبارات القبول في `docs/AI_ASSISTANTS_REQUIREMENTS.md`.

## قاعدة العمل
النطاق كامل: كل ميزات المخطط تُبنى، مرحلة واحدة في كل مرة، على بيئة تطوير ببيانات اصطناعية فقط (انظر `docs/00_BUILD_DIRECTIVE_AR.md`). إن كان المستودع فارغًا فاذكر ذلك ولا تفترض وجود شيء.

ابدأ بتحليل المستودع الموجود فعليًا، ثم قدّم تقريرًا عن الملفات والتقنيات والحالة الحالية. لا تفترض وجود تطبيق أو قاعدة بيانات أو تكاملات لمجرد ذكرها في المخطط. بعد ذلك نفّذ **مرحلة واحدة فقط في كل مرة**، مع اختبارات وملخص واضح للتغييرات.

## ما لا يجوز فعله
- لا تضع بيانات مرضى حقيقية في التطوير أو الاختبارات.
- لا تفعّل رسائل فعلية للمرضى أو تحصيل أموال أو ميزات ذكاء اصطناعي سريرية دون موافقة صريحة واختبارات.
- لا تخترع مفاتيح API أو أسرارًا أو تراخيص بيانات.
- لا تعتبر أي التزام قانوني محسومًا دون مراجعة مختصة موثقة.
- لا تبدأ بميزات المتجر أو الميزات المتقدمة قبل اجتياز أساسيات الأمان وعزل بيانات العيادات والنسخ الاحتياطي.
- لا تحذف ملفات أو تغيّر بنية قاعدة البيانات أو تنفّذ عمليات مدمرة دون خطة ترحيل ونسخ احتياطي وموافقة.

## تعريف النجاح
يُعتبر كل بند منجزًا فقط عندما يوجد تنفيذ فعلي، واختبار مناسب ناجح، ودليل قابل للمراجعة. كتابة كود وحدها لا تعني أن الميزة مكتملة.
