# متطلبات المنتج — منصة إدارة العيادات الطبية

## الرؤية
منصة اشتراكات متعددة العيادات (Multi-Tenant SaaS) للسوق المصري، تدير عمليات العيادات والمراكز الطبية مع فصل صارم بين بيانات كل عميل، وصلاحيات حسب الدور، وإمكانية إضافة الفروع والخدمات تدريجيًا.

## أدوار أساسية يجب التحقق منها في المخطط
- مالك المنصة / الإدارة المركزية.
- مالك العيادة أو مدير المركز.
- الطبيب.
- الاستقبال.
- التمريض أو مساعد الطبيب عند الحاجة.
- المحاسب أو المسؤول المالي.
- موظفو الدعم بصلاحيات محدودة ومراقبة.

لا تفترض أن كل دور يحتاج كل الصلاحيات. يجب إعداد مصفوفة RBAC موثقة قبل التنفيذ.

## مجالات الوظائف
1. حسابات العيادات والاشتراكات والخطط.
2. المستخدمون والأدوار والصلاحيات.
3. الفروع والأطباء والجداول.
4. ملفات المرضى والزيارات والتاريخ الطبي.
5. المواعيد والحضور والإلغاء وإعادة الجدولة.
6. التوثيق الطبي والروشتات والمرفقات، مع سجل تعديل واعتماد.
7. الفواتير والمدفوعات والخصومات والمبالغ المستردة والعمولات حسب نطاق المخطط.
8. التقارير التشغيلية والمالية.
9. الإشعارات والتذكيرات وتكامل واتساب بعد الموافقة والاختبار.
10. منظومة مساعدي الذكاء الاصطناعي: مساعد الطبيب (الأولوية الأولى)، المساعد الإداري (الثانية)، مساعد الاستقبال (الثالثة)، وفق الصلاحيات والموافقات واختبارات القبول في `AI_ASSISTANTS_REQUIREMENTS.md`.
11. قاعدة بيانات الأدوية والتكاملات الخارجية بعد التحقق من الحقوق.
12. النسخ الاحتياطي والمراقبة وسجلات التدقيق والتصدير والخروج.
13. المستلزمات أو المتجر والوظائف المتقدمة في مرحلة لاحقة فقط إذا أكدها المخطط وخطة التنفيذ.

## متطلبات غير وظيفية
- عزل بيانات العملاء على مستوى قاعدة البيانات والخدمات والملفات والتقارير والمهام الخلفية.
- أقل صلاحية لازمة لكل مستخدم وخدمة.
- تشفير النقل والتخزين وإدارة آمنة للمفاتيح والأسرار.
- تسجيل الأحداث الأمنية والإدارية المهمة دون كشف بيانات طبية زائدة.
- حماية من تكرار الطلبات والرسائل والمدفوعات (idempotency).
- قابلية استعادة البيانات واختبار الاستعادة.
- أداء قابل للقياس، ومراقبة أخطاء وتنبيهات.
- تصدير بيانات منظم وقابل للاستعادة.
- دعم العربية واتجاه RTL حيث يلزم، مع التعامل الصحيح مع التواريخ والعملات المصرية.
- إمكانية تعطيل الميزات عالية المخاطر عن طريق feature flags.
- اختبارات آلية للمسارات الحرجة.

## قواعد بيانات المرضى والذكاء الاصطناعي
- يجب التمييز بين بيانات أدخلها المستخدم، وبيانات استخرجها النظام، واستنتاجات الذكاء الاصطناعي.
- لا تُستبدل قيمة مؤكدة تلقائيًا باستنتاج غير مؤكد.
- أي مخرج سريري يحتاج اعتماد الطبيب قبل اعتباره قرارًا أو توجيهًا علاجيًا.
- لا تستخدم بيانات مرضى لتدريب أو أغراض ثانوية دون أساس قانوني وموافقات مناسبة.
- رسائل واتساب تكون مختصرة ولا تكشف تفاصيل طبية حساسة؛ التفاصيل عبر قناة آمنة بعد التحقق من الهوية.

## مبدأ أساسي
هذا الملف يلخّص المتطلبات العامة لتوجيه التنفيذ. عند وجود تعارض، يجب توثيق التعارض والرجوع إلى المخطط الكامل وصاحب المشروع، لا اختراع تفسير صامت.


## منظومة الذكاء الاصطناعي — ترتيب المنتج الملزم
1. **مساعد الطبيب:** صوت/نص إلى مسودة كشف منظمة، ملخص تاريخ طبي موثق المصدر، قراءة تحاليل وتقارير مع إظهار عدم اليقين، وتنبيهات سلامة دوائية من مصدر معتمد. لا تشخيص أو وصفة نهائية آلية؛ اعتماد الطبيب إلزامي.
2. **المساعد الإداري:** مساعد مالك المنصة لتحليل الاشتراكات والتكاليف والأعطال والنمو دون الاطلاع الاعتيادي على تفاصيل المرضى؛ ومساعد صاحب العيادة لتحليل التحصيل والمصروفات والإشغال ومستحقات الأطباء وفق صلاحيات الفرع. الحسابات تنفذها قواعد برمجية معتمدة لا تخمين النموذج.
3. **مساعد الاستقبال:** حجز وتعديل وإلغاء المواعيد عبر واجهات النظام، والتحقق من التوفر والهوية، وإدارة الانتظار والرسائل مع التصعيد البشري للحالات الطبية.

## قرار البنية
بنية هجينة: Backend هو مصدر الحقيقة والصلاحيات وقواعد العمل؛ خدمة AI مستقلة لمعالجة النماذج؛ n8n للأتمتة والتكاملات؛ وطابور مهام للعمليات الطويلة. لا يُسمح للنموذج أو n8n بتجاوز صلاحيات العيادة أو الفرع أو المستخدم. التفاصيل التنفيذية في `AI_ASSISTANTS_REQUIREMENTS.md` و`ARCHITECTURE_AND_SECURITY.md`.
