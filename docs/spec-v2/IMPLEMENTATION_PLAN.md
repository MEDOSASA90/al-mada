# خطة التنفيذ المرحلية

## المرحلة 0 — اكتشاف المستودع والتصميم
- [ ] فحص المستودع والتقنيات الحالية وملفات البيئة.
- [ ] إنشاء تقرير الحالة الحالية.
- [ ] حصر المتطلبات والتعارضات والاعتماديات.
- [ ] توثيق architecture decisions والقرارات المفتوحة.
- [ ] تحديد طريقة تشغيل محلية وبيئة اختبار آمنة.
**بوابة الخروج:** تقرير حالة وخطة معتمدة، دون تغييرات مدمرة.

## المرحلة 1 — أساس التطبيق
- [ ] إعداد المشروع وإعدادات الجودة والتنسيق والفحص.
- [ ] إعداد CI أو فحوصات تلقائية مناسبة للمستودع.
- [ ] إعداد إدارة الأسرار ومتغيرات البيئة.
- [ ] إعداد قاعدة البيانات والترحيلات بطريقة قابلة للمراجعة.
- [ ] إعداد تسجيل الأخطاء والمراقبة الأساسية.
**بوابة الخروج:** التطبيق يعمل في بيئة تطوير، والاختبارات الأساسية تمر.

## المرحلة 2 — الهوية وعزل العيادات
- [ ] تسجيل الدخول وإدارة الجلسات.
- [ ] نموذج العيادات والمستخدمين والأدوار.
- [ ] سياسات عزل البيانات على مستوى الخادم وقاعدة البيانات.
- [ ] اختبارات منع الوصول المتبادل بين العيادات.
- [ ] سجل تدقيق للعمليات الحساسة.
**بوابة الخروج:** اختبارات العزل والصلاحيات ناجحة، ولا توجد بيانات حقيقية.

## المرحلة 3 — النواة التشغيلية
- [ ] الفروع والأطباء والجداول.
- [ ] ملفات المرضى والزيارات والمواعيد.
- [ ] توثيق طبي مع حفظ مصدر المعلومة وسجل التعديلات.
- [ ] الفواتير والحسابات وفق مواصفات واضحة.
- [ ] تقارير أساسية.
**بوابة الخروج:** سيناريوهات العمل الأساسية واختبارات التكامل ناجحة.

## المرحلة 4 — الملفات والتعافي والتصدير
- [ ] رفع وتنزيل آمن للمرفقات.
- [ ] النسخ الاحتياطي والاستعادة.
- [ ] تصدير بيانات العيادة والتحقق من اكتمالها.
- [ ] سياسة احتفاظ وحذف قابلة للتنفيذ.
**بوابة الخروج:** اختبار استعادة وتصدير موثق.

## المرحلة 5 — الاشتراكات والتكاملات
- [ ] خطط الاشتراك وحدود الاستخدام.
- [ ] اختبار دورة الاشتراك والإلغاء والفشل والاسترداد.
- [ ] تكامل الدفع في بيئة اختبار.
- [ ] تكامل واتساب في بيئة اختبار، مع منع الرسائل الحساسة.
**بوابة الخروج:** اختبارات sandbox ناجحة وتكلفة الاستخدام قابلة للقياس.

## المرحلة 6 — الذكاء الاصطناعي
- [ ] تنفيذ أساس البنية الهجينة وسجل المهام والتكلفة والخصوصية.
- [ ] الأولوية الأولى: مساعد الطبيب (صوت/نص إلى مسودة كشف، ملخص التاريخ، قراءة التقارير) مع اعتماد الطبيب واختبارات سريرية مراجعة.
- [ ] الأولوية الثانية: المساعد الإداري لمالك المنصة ثم صاحب العيادة، بعد تثبيت صحة التقارير المالية والتشغيلية.
- [ ] الأولوية الثالثة: مساعد الاستقبال وربطه بالحجز وواتساب عبر واجهات آمنة وn8n.
- [ ] البدء بميزات إدارية منخفضة المخاطر.
- [ ] توثيق مزود النموذج وموقع المعالجة والاحتفاظ وشروط الاستخدام.
- [ ] اختبارات مرجعية ودقة وتحيز وفشل.
- [ ] مراجعة بشرية للنتائج السريرية المقترحة.
- [ ] إمكانية تعطيل الميزات سريعًا.
- [ ] الالتزام التفصيلي بمتطلبات `AI_ASSISTANTS_REQUIREMENTS.md` ومعايير قبول كل مساعد.
**بوابة الخروج:** موافقة صاحب المشروع ومراجعة مختص قبل أي ميزة سريرية.

## المرحلة 7 — الإطلاق التجريبي
- [ ] اختبار أمني وأداء واستعادة.
- [ ] تجربة ببيانات وهمية ثم برنامج تجريبي محدود ومصرح به.
- [ ] مراقبة الأعطال والتكلفة والدعم وسهولة الاستخدام.
- [ ] توثيق إجراءات التشغيل والاستجابة للحوادث.
**بوابة الخروج:** كل معايير القبول الإلزامية ناجحة، والامتثال راجعه مختص.

## المرحلة 8 — التوسع
- [ ] إطلاق تدريجي بالتحكم في الميزات.
- [ ] مراجعة التكلفة والربحية.
- [ ] إضافة الميزات المتقدمة حسب الأولوية والأدلة.
