# تعليمات إلزامية لوكيل البرمجة

> **اقرأ `docs/00_BUILD_DIRECTIVE_AR.md` بعد هذا الملف مباشرة.** هو يحسم التعارضات بين الملفات ويحدد قواعد بيئة التطوير (Supabase/Vercel) وخطة البناء الكاملة. عند تعارض الاثنين تسبق هذه التعليمات.

أنت وكيل هندسي يعمل على بناء منصة SaaS لإدارة العيادات والمراكز الطبية في مصر. اقرأ جميع ملفات `docs/` قبل إجراء تغييرات، وبالأخص `AI_ASSISTANTS_REQUIREMENTS.md` عند التعامل مع أي ميزة ذكاء اصطناعي.

## المرحلة الأولى: اكتشاف الواقع
1. افحص المستودع الحالي والملفات والإعدادات والاعتماديات والاختبارات.
2. لا تفترض أن التقنية المذكورة في المخطط موجودة بالفعل.
3. أخرج `CURRENT_STATE_REPORT.md` يتضمن: ما هو موجود، ما هو مفقود، مخاطر واضحة، أوامر التحقق، والقرارات التي تحتاج صاحب المشروع.
4. لا تبدأ تنفيذ ميزات المنتج قبل تسليم التقرير وخطة المرحلة صفر.

## قواعد التنفيذ
- التزم بالمخطط الكامل، لكن لا تحاول تنفيذ النظام كله دفعة واحدة.
- نفّذ مرحلة واحدة محددة في كل مرة.
- قبل التعديل: اذكر الهدف والملفات المتوقع تغييرها والمخاطر.
- بعد التعديل: شغّل الاختبارات والفحوصات المناسبة، وسجّل النتائج الحقيقية فقط.
- لا تدّع نجاح اختبار لم يتم تشغيله.
- لا تستبدل أو تحذف ملفات قائمة دون فحص محتواها وأثر التغيير.
- حافظ على migrations قابلة للمراجعة، مع سياسة rollback عند الحاجة.
- استخدم بيانات وهمية فقط في بيئات التطوير والاختبار.
- اجعل الأسرار في متغيرات بيئة أو مدير أسرار؛ لا تضعها في المستودع أو السجلات.
- لا ترسل بيانات صحية إلى خدمات خارجية ولا تفعّل تكاملًا مدفوعًا دون مراجعة الخصوصية والتعاقد والتكلفة.
- لا تنفّذ عمليات إنتاجية أو مدمرة، ولا ترسل رسائل فعلية، ولا تحصّل أموالًا دون موافقة صريحة.
- ترتيب أولويات الذكاء الاصطناعي ملزم: مساعد الطبيب أولًا، ثم المساعد الإداري، ثم مساعد الاستقبال.
- اتبع `docs/AI_ASSISTANTS_REQUIREMENTS.md` باعتباره المرجع التفصيلي لمهام المساعدين واختباراتهم وحدودهم.
- اعتمد البنية الهجينة: Backend هو مصدر الحقيقة والصلاحيات وقواعد العمل؛ خدمة AI مستقلة لمعالجة النماذج؛ n8n للأتمتة والتكاملات؛ وطابور مهام للعمليات الطويلة. لا تجعل n8n مصدرًا للصلاحيات أو السجلات الطبية والمالية.
- لا تجعل الذكاء الاصطناعي يصدر تشخيصًا نهائيًا أو روشتة نهائية أو يغيّر علاجًا دون اعتماد الطبيب.
- لا تعتبر مصدر بيانات الأدوية أو الاستضافة أو الامتثال القانوني معتمدًا قبل وجود دليل مكتوب.
- لا تنشئ endpoints أو جداول أو صلاحيات غير موثقة دون تحديث مستندات التصميم والاختبارات.

## مخرجات كل مرحلة
1. ملخص ما تم.
2. قائمة الملفات التي تغيرت.
3. أوامر الاختبار التي شُغّلت ونتائجها.
4. النواقص والمخاطر المتبقية.
5. خطوات التشغيل أو التراجع.
6. تحديث `IMPLEMENTATION_STATUS.md`.

## التوقف وطلب القرار
توقف قبل أي قرار يؤثر في: بيانات المرضى الحقيقية، مكان تخزينها أو نقلها، ترخيص البيانات الدوائية، إرسال رسائل حقيقية، الدفع الفعلي، الاحتفاظ أو الحذف القانوني، أو تفعيل ميزة سريرية. اعرض الخيارات والأثر والتكلفة المتوقعة بدل اختراع قرار.
