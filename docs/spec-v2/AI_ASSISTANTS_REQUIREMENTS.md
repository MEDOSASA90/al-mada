# متطلبات منظومة الذكاء الاصطناعي والمساعدين — وثيقة تنفيذية مستقلة

> هذه الوثيقة مكملة للمخطط الهندسي الكامل، وتُقرأ معه. الأولوية المعتمدة: مساعد الطبيب أولًا، ثم المساعد الإداري، ثم مساعد الاستقبال.

# ملحق متطلبات الذكاء الاصطناعي — النسخة التنفيذية

## 8. الأولويات المعتمدة
1. **مساعد الطبيب الذكي:** أولوية المنتج الأولى، ويُنفّذ ضمن المرحلة الأولى في صورة آمنة قابلة للاختبار.
2. **المساعد الإداري:** أولوية المنتج الثانية، ويُفعّل تدريجيًا بعد توفر بيانات مالية وتشغيلية موثوقة.
3. **مساعد الاستقبال الذكي:** أولوية تالية، مع تنفيذ حجز المواعيد والتذكيرات عبر واجهات النظام ومسارات n8n.
4. لا يلزم إنشاء ثلاثة أنظمة ذكاء اصطناعي منفصلة؛ يمكن استخدام خدمة مشتركة مع أدوات وصلاحيات وسياقات مستقلة لكل دور.

## 9. البنية المعمارية الملزمة للذكاء الاصطناعي
- **الخلفية البرمجية (Backend):** المصدر المعتمد للبيانات والصلاحيات وقواعد العمل الطبية والمالية. لا يجوز للنموذج تجاوز الصلاحيات أو الوصول المباشر غير المقيد إلى قاعدة البيانات.
- **قاعدة البيانات (PostgreSQL/Supabase):** تخزين السجلات المعتمدة، ومسودات الذكاء الاصطناعي، وحالة المهام، والموافقات، وسجل التدقيق.
- **محرك الأتمتة (n8n):** التذكيرات المجدولة، وتكاملات واتساب، وتشغيل المسارات، وإعادة المحاولة، ومعالجة الأحداث. لا يكون مصدر الحقيقة ولا يقرر الصلاحيات.
- **خدمة الذكاء الاصطناعي:** تحويل الصوت إلى نص، واستخراج المعلومات من المستندات، والتلخيص، وتصنيف النصوص، وصياغة المسودات. تُختار الخدمة حسب المهمة والجودة والتكلفة والخصوصية.
- **المهام الخلفية (Background Jobs):** المهام الطويلة مثل الصوت الطويل أو المستندات الكبيرة أو استيراد ملفات كثيرة تُنفذ خارج طلب الشاشة، مع معرف مهمة وحالة تقدم ونتيجة قابلة للمراجعة.
- **واجهات آمنة:** جميع الاتصالات مصادق عليها، ومحددة الصلاحيات، ومقيدة بمستوى العيادة والفرع والمريض، مع حماية الأسرار ومفاتيح الخدمة.
- **عدم تعطيل الاستخدام:** لا ينتظر الطبيب انتهاء مهمة طويلة في نفس طلب الواجهة؛ تظهر له حالة مثل قيد المعالجة، اكتملت، تحتاج مراجعة، أو فشلت.
- **ضبط التكلفة:** تسجيل عدد الطلبات ومدة التنفيذ والتكلفة التقديرية ومعدل الفشل لكل عيادة ولكل ميزة، مع حدود استخدام وتنبيهات وخيار إيقاف أو تحويل المهمة إلى مسار بديل.
- **الاعتمادية:** استخدام معرفات فريدة للطلبات لمنع التكرار، وإعادة محاولة محسوبة، وطابور فشل للمراجعة، ومراقبة زمن الانتظار ومعدلات الأخطاء.
- **الخصوصية:** إرسال الحد الأدنى اللازم فقط إلى مزود الذكاء الاصطناعي، وعدم استخدام بيانات المرضى لتدريب النماذج دون أساس قانوني وموافقة مناسبة. يجب مراجعة متطلبات حماية البيانات الصحية المصرية ومكان المعالجة والاحتفاظ قبل الإطلاق.

## 10. مساعد الطبيب الذكي — المتطلبات التفصيلية

### 10.1 الهدف
تقليل وقت التوثيق وتحسين تنظيم المعلومات الطبية مع بقاء التشخيص النهائي والقرارات العلاجية والوصفة الطبية تحت مسؤولية الطبيب المعتمد.

### 10.2 طرق الإدخال
- إملاء صوتي باللهجة المصرية أو العربية الفصحى، مع دعم إدخال النص يدويًا.
- نقاط سريعة يكتبها الطبيب أو يختارها من قوالب تخصصه.
- بيانات المريض السابقة التي يملك الطبيب صلاحية الاطلاع عليها.
- القياسات الحيوية المسجلة بواسطة التمريض.
- نتائج التحاليل والتقارير والمرفقات المتاحة في ملف المريض.
- قوالب الكشف وخطة العلاج والمتابعة المعرفة للتخصص والعيادة.

### 10.3 المخرجات
ينشئ المساعد **مسودة غير معتمدة** تتضمن الحقول المناسبة للتخصص، ومنها:
- الشكوى الرئيسية ومدة الأعراض كما وردت.
- التاريخ المرضي السابق والأدوية والحساسية ذات الصلة.
- القياسات الحيوية مع تاريخ تسجيلها ومصدرها.
- الفحص السريري فقط إذا أدخله الطبيب أو ورد في مصدر موثوق محدد؛ لا يُنشئ فحصًا لم يحدث.
- التشخيص أو الاحتمالات التي ذكرها الطبيب، مع فصل اقتراح الذكاء الاصطناعي بوضوح عن قرار الطبيب.
- خطة العلاج والتعليمات والمتابعة كما أملاها الطبيب.
- مسودة الروشتة بأسماء الأدوية والجرعات والتكرار والمدة والطريق الدوائي إذا كانت مذكورة بوضوح.
- طلبات التحاليل والأشعة والإجراءات التي ذكرها الطبيب.
- الحقول الناقصة والتناقضات والأسئلة التي تحتاج إلى مراجعة.
- ملخص قصير للزيارة يصلح للمراجعة قبل الاعتماد.

### 10.4 ضوابط الصوت والتحويل
- إظهار النص المستخرج قبل تحويله إلى سجل طبي نهائي.
- إبراز الكلمات أو الأسماء أو الأرقام أو الجرعات منخفضة الثقة بدل تصحيحها بالتخمين.
- الاحتفاظ برابط التسجيل أو النص الأصلي فقط وفق سياسة احتفاظ واضحة وموافقة مناسبة.
- تمكين الطبيب من تعديل النص والمسودة بسهولة، ثم اعتماد النسخة النهائية.
- عدم تنفيذ أي إرسال للمريض أو وصفة إلكترونية تلقائيًا قبل اعتماد الطبيب.

### 10.5 ملخص التاريخ الطبي
- تلخيص الزيارات السابقة زمنيًا مع التاريخ ومصدر المعلومة.
- التمييز بين معلومة مؤكدة، ومعلومة منقولة، ومعلومة ناقصة أو متعارضة.
- عرض الحساسية والأدوية الحالية والأمراض المزمنة والنتائج المهمة عند توافرها.
- عدم اعتبار ملخص الذكاء الاصطناعي بديلًا عن السجل الأصلي؛ يجب فتح المصدر الأصلي بسهولة.
- تحديث الملخص بعد اعتماد السجل الجديد، مع تسجيل وقت التحديث ومصدر البيانات.

### 10.6 قراءة التحاليل والتقارير
- استخراج اسم الفحص والقيمة والوحدة والمدى المرجعي والتاريخ إذا كانت ظاهرة.
- ربط كل معلومة بالصفحة أو موضعها في الملف متى أمكن.
- عرض النص أو الصورة الأصلية بجانب الاستخراج للمراجعة.
- عدم استنتاج نتيجة غير موجودة أو تحويل الوحدات دون توضيح.
- إذا كانت الصورة غير واضحة أو القيمة غير مؤكدة، تُعلّم بأنها تحتاج مراجعة ولا تُستخدم كحقيقة مؤكدة.

### 10.7 تنبيهات السلامة الدوائية
- التحقق من الحساسية والتعارضات والجرعات والتنبيهات ذات الصلة باستخدام مرجع دوائي موثوق ومحدّث، عند توفر تكامل معتمد.
- توضيح سبب كل تنبيه ومصدره وتاريخ المرجع أو نسخته متى توفر.
- عدم اختراع جرعة أو بديل أو تفاعل دوائي عند غياب البيانات.
- إذا كانت بيانات العمر أو الوزن أو وظائف الكلى أو الحمل أو غيرها لازمة للتحقق وغير متاحة، يطلب المساعد مراجعتها بدل التخمين.
- لا يصدر المساعد وصفة مستقلة ولا يغيّر علاجًا معتمدًا من تلقاء نفسه.
- لا يُسوّق التنبيه على أنه ضمان لسلامة الدواء أو بديل عن الحكم الطبي.

### 10.8 الصلاحيات والموافقة
- الطبيب يرى ملفات المرضى المسندة إليه أو المسموح بها حسب إعدادات العيادة والفرع.
- التمريض يمكنه إدخال القياسات المصرح بها، ولا يستطيع اعتماد تشخيص أو روشتة بصفته التمريضية.
- الاستقبال لا يرى تفاصيل التشخيص أو الملاحظات السريرية إلا إذا كانت هناك صلاحية صريحة وضرورة عمل.
- مالك المنصة لا يطّلع تلقائيًا على تفاصيل ملفات المرضى لمجرد امتلاكه المنصة؛ وصول الدعم الاستثنائي يجب أن يكون مقيدًا ومبررًا ومسجلًا.
- لا تحفظ المسودة كسجل نهائي ولا ترسل الوصفة قبل موافقة الطبيب.
- كل تعديل واعتماد وإرسال ورفض وتنبيه مهم يُسجل مع المستخدم والتوقيت والإصدار.

### 10.9 حالات المسودة
`created` (أُنشئت) → `processing` (قيد المعالجة) → `draft_ready` (مسودة جاهزة) → `needs_review` (تحتاج مراجعة) → `approved` (معتمدة من الطبيب) أو `rejected` (مرفوضة) أو `failed` (فشلت المعالجة).
- لا يمكن الانتقال إلى `approved` إلا بواسطة طبيب مخول.
- عند فشل المعالجة، يظل الإدخال الأصلي متاحًا ولا يُفقد.
- عند تعديل الطبيب للمسودة، يُحفظ الفرق بين المسودة والنسخة المعتمدة لأغراض التدقيق.

### 10.10 اختبارات القبول لمساعد الطبيب
1. تسجيل صوتي واضح باللهجة المصرية ينتج مسودة منظمة دون فقد المعلومات الأساسية.
2. صوت يحتوي على جرعة غير واضحة ينتج تنبيهًا للمراجعة ولا يخترع الجرعة.
3. لا تظهر بيانات مريض من عيادة أخرى في أي نتيجة أو سياق.
4. لا يستطيع موظف استقبال اعتماد وصفة أو الاطلاع على تفاصيل سريرية غير مصرح بها.
5. لا تُرسل وصفة أو رسالة للمريض قبل اعتماد الطبيب.
6. كل معلومة مستخرجة من تقرير ترتبط بمصدرها متى أمكن، ويظهر عدم اليقين بوضوح.
7. عند تعطل مزود الذكاء الاصطناعي، يظل النظام اليدوي متاحًا وتظهر حالة الفشل دون ضياع المدخل.
8. كل مسودة واعتماد وتعديل وإرسال يمكن تتبعها في سجل التدقيق.
9. قياس الدقة ومعدل الأخطاء وزمن الاستجابة والتكلفة على عينة اختبار يراجعها أطباء من التخصص المعني قبل الإطلاق.

## 11. المساعد الإداري الذكي — المتطلبات التفصيلية

### 11.1 مساعد مالك المنصة
- تلخيص عدد العيادات النشطة والجديدة والمتوقفة وحالات الاشتراك.
- تحليل الاشتراكات والإيرادات المستحقة والمحصلة والمتأخرة، مع التمييز بين الإيراد المحاسبي والتحصيل النقدي.
- مراقبة استهلاك الذكاء الاصطناعي وواتساب وتكلفة كل عيادة وميزة.
- اكتشاف مؤشرات الأعطال أو ارتفاع معدلات الفشل أو بطء المهام وتلخيصها.
- عرض استخدام الميزات ومؤشرات الاحتفاظ والإلغاء والنمو عندما تكون البيانات متاحة.
- إعداد تقارير يومية وأسبوعية وشهرية مع روابط إلى الأرقام الأصلية.
- اقتراح إجراءات لتحسين التشغيل أو تقليل التكلفة، دون تنفيذ تغييرات حساسة تلقائيًا.
- لا يقرأ التفاصيل الطبية للمرضى ضمن التحليلات المعتادة؛ تُستخدم مؤشرات مجمعة أو منزوعة الهوية متى أمكن.
- أي إجراء مؤثر على الاشتراكات أو الفواتير أو الحسابات أو الوصول يتطلب صلاحية صريحة وتأكيدًا قبل التنفيذ.

### 11.2 مساعد صاحب العيادة أو مدير المركز
- تلخيص الإيرادات المحصلة والمستحقات والمصروفات وصافي النتيجة وفق تعريف محاسبي واضح.
- تحليل إشغال المواعيد والإلغاء وعدم الحضور والانتظار لكل طبيب وفرع.
- إظهار مستحقات الأطباء والخصومات والمبالغ غير المسددة مع الرجوع للسجلات المصدرية.
- الإجابة عن أسئلة بلغة طبيعية مثل: «إيه إجمالي التحصيل النهارده؟» أو «إيه أكتر الفترات اللي فيها مواعيد فاضية؟».
- اقتراح مواعيد حملات تذكير أو إعادة حجز، دون إرسال حملات قبل اعتمادها واحترام موافقات المرضى.
- كشف التناقضات المحتملة في الأرقام وعرضها للمراجعة بدل تعديل السجلات تلقائيًا.
- احترام صلاحيات الفرع والدور؛ مدير الفرع لا يرى تلقائيًا بيانات فروع أخرى.
- جميع العمليات الحسابية المالية تُنفذ بكود وقواعد محاسبية معتمدة في الخلفية، وليس بتقدير لغوي من نموذج الذكاء الاصطناعي.

### 11.3 اختبارات القبول للمساعد الإداري
1. كل رقم مالي في الإجابة يمكن تتبعه إلى تقرير أو سجلات محددة وفترة زمنية معلومة.
2. لا يخترع المساعد أرقامًا عند نقص البيانات؛ يوضح النقص ويطلب مراجعة السجل.
3. لا يستطيع مستخدم محدود الصلاحيات الوصول إلى تقارير أعلى من صلاحياته.
4. لا يُنفذ خصم أو استرداد أو تغيير اشتراك أو إرسال حملة حساسة دون تأكيد مخول.
5. توضح التقارير الفترة الزمنية والفرع وتعريف المؤشر المستخدم.
6. تُقارن الحسابات بنتائج التقارير المعتمدة في اختبارات آلية قبل الإطلاق.

## 12. مساعد الاستقبال الذكي
- حجز المواعيد وتعديلها وإلغاؤها من خلال واجهات النظام المعتمدة فقط.
- التحقق من التوفر في الخلفية ومنع الحجز المزدوج.
- الرد على الأسئلة الإدارية المعتمدة عن المواعيد والموقع والخدمات والأسعار التي أدخلتها العيادة.
- إدارة قائمة الانتظار والتذكيرات، مع منع إرسال الرسائل دون الموافقات المطلوبة.
- تصعيد الحالات الطبية أو الطارئة إلى موظف أو جهة مناسبة، وعدم تشخيص المريض عبر البوت.
- التحقق من هوية المتحدث قبل الإفصاح عن بيانات أو مستندات شخصية.
- لا يعرض تشخيصًا أو روشتة أو تفاصيل سريرية لمجرد معرفة رقم هاتف المريض.

## 13. مستويات تنفيذ المساعدين
1. **شرح واسترجاع:** الإجابة من بيانات مسموح بها مع إظهار المصدر.
2. **صياغة مسودة:** إعداد كشف أو تقرير أو رسالة للمراجعة.
3. **تنفيذ محدود:** تنفيذ إجراءات منخفضة المخاطر ضمن صلاحية واضحة مثل حجز متاح، مع تسجيل العملية.
4. **سير عمل متعدد الخطوات:** يطلب تأكيدًا بشريًا عند وجود أثر مالي أو طبي أو خصوصي أو عند وجود غموض غير متوقع.

## 14. سجل موحد لتشغيل الذكاء الاصطناعي
يُسجل لكل مهمة: معرف المهمة، العيادة والفرع، المستخدم ودوره، نوع المهمة، مزود النموذج وإصداره عند توفرهما، وقت البدء والانتهاء، الحالة، التكلفة التقديرية، نتيجة التحقق، ومراجع السجلات التي استخدمت. تُحجب الأسرار والبيانات الطبية غير اللازمة عن سجلات التشغيل. وتُحدد مدد الاحتفاظ والوصول وفق سياسة الخصوصية.

## 15. خطة التنفيذ والقياس
### المرحلة الأولى — أساس مساعد الطبيب
- اعتماد مسار صوت/نص → مسودة كشف → مراجعة الطبيب → اعتماد.
- دعم قوالب التخصصات، والتاريخ المرضي، والمرفقات، وسجل التعديلات.
- اختبار عزل البيانات والصلاحيات والفشل والاستعادة قبل تشغيله على بيانات حقيقية.
- عدم تفعيل اقتراحات دوائية تعتمد على مصادر خارجية إلا بعد اعتماد مصدر دوائي موثوق وتوثيق طريقة تحديثه.

### المرحلة الثانية — المساعد الإداري
- بناء تقارير مالية وتشغيلية موثوقة أولًا.
- ربط المساعد بالتقارير المسموح بها، مع تفسير الأرقام وإظهار الفترة والفلاتر.
- إضافة التنبيهات والتحليلات والتوصيات، ثم الإجراءات التي تتطلب تأكيدًا.

### المرحلة الثالثة — الاستقبال والأتمتة المتقدمة
- ربط واتساب والحجز والتذكيرات وقائمة الانتظار عبر n8n وواجهات آمنة.
- تفعيل استيراد البيانات وقراءة المستندات تدريجيًا بعد اختبارات الجودة والخصوصية.

## 16. شروط الإطلاق
- مراجعة أمنية لصلاحيات العيادات والفروع والمرضى.
- اختبارات قبول يشارك فيها أطباء ومستخدمون من الأدوار المختلفة.
- سياسة واضحة للخصوصية والموافقة والاحتفاظ بالبيانات.
- مراقبة التكلفة والدقة والفشل وزمن الاستجابة، مع حدود استخدام لكل عيادة.
- خطة نسخ احتياطي واستعادة مجرّبة، وسجل تدقيق للتغييرات الحساسة.
- مراجعة قانونية وتنظيمية محلية قبل الإطلاق التجاري، خاصة التعامل مع البيانات الصحية والرسائل الإلكترونية والسجلات الطبية.
- أي ميزة لم يتم اختبارها أو لا يتوفر لها مصدر موثوق تبقى معطلة أو تجريبية بوضوح، ولا تُعرض كميزة آمنة مكتملة.
